# ADR-008: Patient-Specific CPTs, Default Administrator, and Shared Registry

- **Status:** Accepted; CPT lifecycle completed by ADR-009
- **Date:** 2026-08-21
- **Scope:** Bayesian parameter generation, initial Administrator credentials, Psychiatrist patient visibility

## Context

The detailed workflow requires an LLM, acting as MCP client, to fill Bayesian probability tables from each patient's accumulated data before extracting network results. It also specifies an initial `admin/admin` account and states that Psychiatrists can see previous patients. These requirements conflict with earlier assumptions of fixed model CPTs, secure one-time bootstrap credentials, and creator-scoped patient visibility.

## Decision

### Patient-specific CPT generation

For each Bayesian execution, the hosted LLM regenerates every conditional probability table from the de-identified Research Case context and the active base model's topology, nodes, outcomes, and table shapes. No CPT from the base model remains numerically authoritative for that execution.

The generated tables are an immutable per-execution snapshot. They do not overwrite the active base model, change another patient's calculations, or become a globally active model version. INSIGHT stores:

- active base-model version and content hash;
- de-identified model-visible input snapshot;
- LLM provider, model identifier, and model-version metadata;
- prompt/template and output-schema versions;
- sampling and generation settings;
- raw structured CPT response;
- accepted CPT snapshot used for inference;
- validation diagnostics and retry history;
- deterministic inference results;
- timestamps and initiating Psychiatrist;
- resulting explanation and treatment-plan linkage.

Before inference, the BN MCP server must reject generated tables with incorrect dimensions, missing rows, non-finite numbers, negative probabilities, or nature-node rows that do not sum to one within the configured tolerance. A required BN failure blocks finalization under ADR-005.

Inference after CPT acceptance is deterministic for the stored snapshot. Re-running LLM generation may produce different tables; reproducibility therefore means preserving and replaying the accepted snapshot, not assuming that the hosted model will regenerate identical values.

The generated CPTs are not calibrated clinical probabilities merely because they pass mathematical checks. The Psychiatrist UI must identify them as LLM-generated, patient-specific research values.

All de-identified patient context affects the Bayesian result only through CPT generation. The inference engine does not separately enter any patient fact as observed BN evidence and does not clamp patient-state nodes. This avoids using the same fact through both CPT generation and evidence conditioning.

Consequently, INSIGHT is not performing ordinary Bayesian updating against observed patient states. It performs deterministic inference over a fully patient-parameterized network whose numerical tables were generated by the LLM. ADR-009 defines validation retries, invalidation, and snapshot reuse.

### Default Administrator credential

Every installation creates an enabled Administrator account with username `admin` and password `admin`. INSIGHT does not force a password change at first sign-in. The Administrator may voluntarily change the username or password later.

This credential is publicly predictable. Until changed, anyone who can reach the sign-in page can attempt full Administrator access. Rate limiting and password hashing do not make a known password secret. This is an accepted critical security limitation of the selected bootstrap policy.

Administrator patient-content isolation from ADR-007 still applies, but a compromised Administrator can create accounts, change other users' credentials, alter knowledge artifacts, roll back models, modify configuration, inspect non-clinical logs, and perform backup or restore operations.

### Shared patient registry

All Psychiatrists can locate, view, edit, and finalize all Patient records and Research Cases in the deployment. Access is not limited by the Psychiatrist who created the Patient or Research Case. `createdBy` remains attributable metadata, not an authorization boundary.

The shared registry uses the canonical UUID and mandatory official identifier to prevent duplicate patient identities. Search results must mask the official identifier except where disclosure is necessary to disambiguate matching records.

Administrator access remains prohibited. Every Psychiatrist has the same patient-content authority; authorship affects attribution only.

## Consequences

- Bayesian outputs depend directly on hosted-LLM probability generation rather than only on a pre-calibrated model.
- Every numerical CPT is replaced per execution, so base-model clinical calibration does not carry into the patient-specific network.
- Patient observations are not clamped as evidence; their effect exists only through the LLM's generated probabilities.
- Mathematical CPT validity does not establish clinical validity, calibration, or stable behavior across equivalent prompts.
- Stored generation artifacts become part of treatment-plan provenance and may materially increase sensitive audit storage.
- A default unchanged `admin/admin` credential creates an immediate account-takeover path.
- Shared visibility increases collaboration but exposes every identified research record to every Psychiatrist account.
- Last-write-wins behavior can cause cross-Psychiatrist draft changes to be silently overwritten.

## Bootstrap Account Resolution

Deployment configuration cannot suppress creation of the enabled `admin/admin` account. After installation it follows ordinary Administrator account-management rules: its username/password can change, and it may be disabled only when another enabled Administrator exists.

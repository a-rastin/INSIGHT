## Tracker Maintenance Rule

- Each implementation package must have it's own markdown progress tracker file inside this path: "CONTEXT/PROGRESS-TRACKER".
- Keep this file focused on current state, active risks, next packets, and concise completed outcomes.
- Add each new implementation packet using `CONTEXT/TEMPLATES/progress-entry-template.md` while work is active.
- After the packet is superseded or its next issue is completed, fold it into the ledger and rely on Git history for exact command transcripts and detailed rollback evidence.
- Do not remove unresolved clinical, security, compatibility, data-recovery, or verification limitations during compaction.
